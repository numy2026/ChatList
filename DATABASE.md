# Схема базы данных ChatList

База данных: **SQLite**. Все таблицы создаются при первом запуске (модуль `db.py`).

---

## 1. Таблица `prompts` (промты)

Хранит сохранённые запросы пользователя.

| Поле      | Тип        | Описание                          |
|-----------|------------|-----------------------------------|
| id        | INTEGER    | Первичный ключ, автоинкремент    |
| created_at| TEXT/DATETIME | Дата и время создания записи   |
| prompt    | TEXT       | Текст промта (запроса)            |
| tags      | TEXT       | Теги (например, через запятую или JSON) |

- **Индексы:** по `created_at`, по `tags` (при необходимости поиска по тегам).

---

## 2. Таблица `models` (нейросети)

Справочник моделей и параметров доступа к API. API-ключи в таблице не хранятся — только имя переменной окружения.

| Поле     | Тип     | Описание |
|----------|---------|----------|
| id       | INTEGER | Первичный ключ, автоинкремент |
| name     | TEXT    | Название модели (для отображения) |
| api_url  | TEXT    | URL API (например, `https://api.openai.com/v1/chat/completions`) |
| api_id   | TEXT    | Имя переменной в `.env`, где лежит API-ключ (например, `OPENAI_API_KEY`) |
| is_active| INTEGER | Признак активности (1 — участвует в запросах, 0 — нет) |

- **Уникальность:** при необходимости — уникальное ограничение по `name` или по паре `(api_url, api_id)`.
- **Индексы:** по `is_active` для быстрой выборки активных моделей.

---

## 3. Таблица `results` (сохранённые результаты)

Хранит ответы моделей, которые пользователь отметил и сохранил.

| Поле       | Тип     | Описание |
|------------|---------|----------|
| id         | INTEGER | Первичный ключ, автоинкремент |
| created_at | TEXT/DATETIME | Дата и время сохранения |
| prompt_id  | INTEGER | Внешний ключ на `prompts.id` (какой промт был отправлен) |
| model_id   | INTEGER | Внешний ключ на `models.id` (какая модель ответила) |
| model_name | TEXT   | Название модели на момент сохранения (дублирование для истории) |
| response   | TEXT    | Текст ответа модели |

- **Внешние ключи:** `prompt_id` → `prompts(id)`, `model_id` → `models(id)`.
- **Индексы:** по `prompt_id`, по `model_id`, по `created_at` для поиска и сортировки.

При желании можно добавить поле `prompt_text` (копия промта на момент запроса) для отображения без джойна с `prompts`.

---

## 4. Таблица `settings` (настройки программы)

Хранение настроек в виде ключ–значение.

| Поле  | Тип    | Описание |
|-------|--------|----------|
| id    | INTEGER| Первичный ключ, автоинкремент |
| key   | TEXT   | Уникальный ключ настройки (например, `theme`, `last_model_ids`) |
| value | TEXT   | Значение (строка или JSON) |

- **Уникальность:** по полю `key`.
- **Индекс:** по `key` для быстрого доступа.

---

## Связи (ER, кратко)

- **prompts** — независимая таблица; на неё ссылается **results** через `prompt_id`.
- **models** — независимая таблица; на неё ссылается **results** через `model_id`.
- **results** — дочерняя к `prompts` и к `models`.
- **settings** — независимая таблица ключ–значение.

---

## Временная таблица (не в SQLite)

Результаты текущего запроса до нажатия «Сохранить» хранятся **в памяти** (например, список словарей или объекты с полями):

- `model_id` / `model_name`
- `response` — текст ответа
- `selected` — булево (отмечен ли пользователем для сохранения)
- при необходимости: `error` — сообщение об ошибке запроса

После «Сохранить» отмеченные строки переносятся в таблицу `results`; временная структура очищается или пересобирается при следующей отправке.
