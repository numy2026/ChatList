# План реализации ChatList

Поэтапный порядок действий по реализации программы на основании PROJECT.md.

---

## Этап 1. Подготовка проекта

1. Зафиксировать структуру каталогов и зависимости (Python 3.11+, PyQt5, requests/httpx, python-dotenv для .env).
2. Добавить в `requirements.txt` все нужные пакеты.
3. Описать формат `.env`: переменные для API-ключей (имена переменных соответствуют полю `api_id` в таблице models).
4. Добавить `.env.example` без секретов, с перечислением переменных.

---

## Этап 2. База данных (модуль db.py)

1. Реализовать подключение к SQLite и инициализацию БД (создание таблиц при первом запуске).
2. Реализовать CRUD для таблицы **prompts** (дата, промт, теги).
3. Реализовать CRUD для таблицы **models** (name, api_url, api_id, is_active).
4. Реализовать CRUD для таблицы **results** (связь с промптом и моделью, текст ответа и др. поля по схеме).
5. Реализовать CRUD для таблицы **settings** (хранение настроек программы).
6. Инкапсулировать весь доступ к SQLite в `db.py`; остальной код с БД напрямую не работает.

---

## Этап 3. Логика моделей (модуль models.py)

1. Реализовать получение списка активных моделей (выборка из БД по `is_active = 1`).
2. Реализовать чтение API-ключа из окружения по имени переменной из поля `api_id`.
3. При необходимости — маппинг типа модели (OpenAI, DeepSeek, Groq и т.д.) для этапа отправки запросов.

---

## Этап 4. Сетевой слой (модуль network.py)

1. Реализовать отправку одного промта в одну модель (функция/метод с параметрами: промт, модель, API-ключ/URL).
2. Реализовать цикл: для каждого активной модели отправить промт и собрать ответы в единую структуру (список словарей: модель, ответ, ошибка при наличии).
3. Обработка ошибок сети и API (таймауты, 4xx/5xx, неверный ключ).
4. Не сохранять ответы в SQLite в этом модуле — только возвращать данные для временной таблицы в GUI.

---

## Этап 5. Временная таблица результатов (в памяти)

1. Определить структуру «временной таблицы» в коде (например, список словарей или объекты с полями: модель, текст ответа, selected).
2. При новом запросе — полностью очищать эту структуру и заполнять заново после вызова network.py.
3. При нажатии «Сохранить» — передавать в db.py только строки с `selected = True` для записи в таблицу results.

---

## Этап 6. Интерфейс (main.py / GUI)

1. Окно приложения: область ввода промта, кнопка «Отправить» (или аналог), список/таблица результатов, кнопка «Сохранить».
2. Реализовать ввод нового промта и выбор сохранённого промта из таблицы prompts (выпадающий список или отдельное окно/панель).
3. По «Отправить»: вызвать models.py для списка активных моделей, затем network.py; обновить временную таблицу и отобразить её в GUI (название модели, текст ответа, чекбокс selected).
4. Реализовать кнопку «Сохранить»: записать выбранные строки в таблицу results через db.py, очистить временную таблицу от сохранённых и обновить вид.
5. При смене промта (новый ввод или выбор другого сохранённого) — очистить временную таблицу и при следующей отправке построить её заново.
6. Подключить все действия к соответствующим модулям (db, models, network).

---

## Этап 7. Интеграция и проверка

1. Проверить полный сценарий: ввод промта → отправка → отображение результатов → выбор строк → сохранение в results.
2. Проверить сценарий с сохранённым промтом из prompts.
3. Убедиться, что API-ключи берутся только из .env по именам из models.api_id.

---

## Этап 8. Дополнительные функции (опционально)

1. **Поиск и сортировка** — во всех экранах/таблицах (prompts, models, results, settings) реализовать поиск и сортировку по столбцам.
2. **Экспорт** — экспорт выбранных результатов в Markdown и/или JSON.
3. **Типы моделей** — поддержка разных провайдеров (OpenAI, DeepSeek, Groq и т.д.) через отдельные обработчики в network.py или подмодули.
4. **Логи** — логирование запросов к API (в файл и/или в таблицу БД).

---

Порядок выполнения: этапы 1–6 обязательны для минимально рабочей программы; этап 7 — проверка; этап 8 — по возможности.
