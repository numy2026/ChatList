# План реализации ChatList

Поэтапный порядок действий по реализации программы на основании PROJECT.md.

---

## Этап 1. Подготовка проекта

1. Зафиксировать структуру каталогов и зависимости (Python 3.11+, PyQt5, requests/httpx, python-dotenv для .env).
2. Добавить в `requirements.txt` все нужные пакеты.
3. Описать формат `.env`: переменные для API-ключей (имена переменных соответствуют полю `api_id` в таблице models).
4. Добавить `.env.example` без секретов, с перечислением переменных.

---

## Этап 2. База данных (модуль db.py)

1. Реализовать подключение к SQLite и инициализацию БД (создание таблиц при первом запуске).
2. Реализовать CRUD для таблицы **prompts** (дата, промт, теги).
3. Реализовать CRUD для таблицы **models** (name, api_url, api_id, is_active).
4. Реализовать CRUD для таблицы **results** (связь с промптом и моделью, текст ответа и др. поля по схеме).
5. Реализовать CRUD для таблицы **settings** (хранение настроек программы).
6. Инкапсулировать весь доступ к SQLite в `db.py`; остальной код с БД напрямую не работает.

---

## Этап 3. Логика моделей (модуль models.py)

1. Реализовать получение списка активных моделей (выборка из БД по `is_active = 1`).
2. Реализовать чтение API-ключа из окружения по имени переменной из поля `api_id`.
3. При необходимости — маппинг типа модели (OpenAI, DeepSeek, Groq и т.д.) для этапа отправки запросов.

---

## Этап 4. Сетевой слой (модуль network.py)

1. Реализовать отправку одного промта в одну модель (функция/метод с параметрами: промт, модель, API-ключ/URL).
2. Реализовать цикл: для каждого активной модели отправить промт и собрать ответы в единую структуру (список словарей: модель, ответ, ошибка при наличии).
3. Обработка ошибок сети и API (таймауты, 4xx/5xx, неверный ключ).
4. Не сохранять ответы в SQLite в этом модуле — только возвращать данные для временной таблицы в GUI.

---

## Этап 5. Временная таблица результатов (в памяти)

1. Определить структуру «временной таблицы» в коде (например, список словарей или объекты с полями: модель, текст ответа, selected).
2. При новом запросе — полностью очищать эту структуру и заполнять заново после вызова network.py.
3. При нажатии «Сохранить» — передавать в db.py только строки с `selected = True` для записи в таблицу results.

---

## Этап 6. Интерфейс (main.py / GUI)

1. Окно приложения: область ввода промта, кнопка «Отправить» (или аналог), список/таблица результатов, кнопка «Сохранить».
2. Реализовать ввод нового промта и выбор сохранённого промта из таблицы prompts (выпадающий список или отдельное окно/панель).
3. По «Отправить»: вызвать models.py для списка активных моделей, затем network.py; обновить временную таблицу и отобразить её в GUI (название модели, текст ответа, чекбокс selected).
4. Реализовать кнопку «Сохранить»: записать выбранные строки в таблицу results через db.py, очистить временную таблицу от сохранённых и обновить вид.
5. При смене промта (новый ввод или выбор другого сохранённого) — очистить временную таблицу и при следующей отправке построить её заново.
6. Подключить все действия к соответствующим модулям (db, models, network).

---

## Этап 7. Интеграция и проверка

1. Проверить полный сценарий: ввод промта → отправка → отображение результатов → выбор строк → сохранение в results.
2. Проверить сценарий с сохранённым промтом из prompts.
3. Убедиться, что API-ключи берутся только из .env по именам из models.api_id.

---

## Этап 8. Дополнительные функции (опционально)

1. **Поиск и сортировка** — во всех экранах/таблицах (prompts, models, results, settings) реализовать поиск и сортировку по столбцам.
2. **Экспорт** — экспорт выбранных результатов в Markdown и/или JSON.
3. **Типы моделей** — поддержка разных провайдеров (OpenAI, DeepSeek, Groq и т.д.) через отдельные обработчики в network.py или подмодули.
4. **Логи** — логирование запросов к API (в файл и/или в таблицу БД).

---

## Этап 9. AI-ассистент для улучшения промтов (PROJECT.md, п. 7)

План реализации функции «AI-ассистент для улучшения промтов».

### 9.1 Требования к функции (из спецификации)

- Принимать исходный текст промта от пользователя.
- Отправлять его в **одну указанную модель** через существующий Open Router–клиент (network.py).
- Возвращать:
  - улучшенную версию промта;
  - 2–3 варианта переформулировки;
  - при необходимости — адаптацию под типы задач (код, анализ, креатив).
- Встраивать в UI: кнопка «Улучшить промт», окно с результатами, подстановка выбранного варианта в поле ввода.

### 9.2 Бэкенд: запрос к одной модели и парсинг ответа

1. **Выбор модели для ассистента**
   - Добавить в настройки (settings или отдельный комбобокс) выбор «модели для улучшения промта» (одна из активных моделей из таблицы models).
   - Либо использовать первую активную модель по умолчанию, либо хранить `prompt_improver_model_id` в settings.

2. **Системный промт для улучшения**
   - Сформировать фиксированный системный промт (или шаблон), в котором задаётся роль: «Ты помогаешь улучшать пользовательские промты для LLM. Верни: 1) улучшенный промт; 2) 2–3 варианта переформулировки; при необходимости — варианты под задачи: код, анализ, креатив. Формат: структурированный текст с явными заголовками/секциями (например Markdown).»
   - Хранить шаблон в коде (константа) или в settings для возможности правки.

3. **Один запрос к API**
   - В network.py уже есть `send_prompt_to_model(prompt, model, ...)`. Для ассистента нужен запрос с **двумя сообщениями**: system (инструкция по улучшению) и user (исходный промт пользователя).
   - Добавить в network.py функцию, например `improve_prompt_via_model(prompt: str, model: dict, system_prompt: str) -> dict` (ответ или ошибка), либо расширить существующий вызов поддержкой списка сообщений `messages: [{role: "system", content: ...}, {role: "user", content: ...}]`.

4. **Парсинг ответа модели**
   - Ответ модели — один текст (Markdown или с разделами). Реализовать парсер (в отдельном модуле, например `prompt_improver.py`), который из текста ответа извлекает:
     - улучшенный промт (одна строка или блок);
     - список из 2–3 альтернативных формулировок;
     - опционально: варианты по типам (код / анализ / креатив).
   - Парсинг может быть по заголовкам (## Улучшенный промт, ## Варианты и т.д.) или по маркерам. При неудачном разборе — показывать весь ответ как один вариант «улучшенный промт».

### 9.3 Модуль логики (prompt_improver.py)

1. Вынести логику в модуль `prompt_improver.py`:
   - константа или загрузка системного промта;
   - вызов network (одна модель, сообщения system + user);
   - парсинг ответа в структуру: `{ "improved": str, "alternatives": [str, ...], "by_type": {"код": str, "анализ": str, "креатив": str} }` (последнее опционально).
2. Обработка ошибок: таймаут, HTTP-ошибка, невалидный ответ — возвращать понятное сообщение в UI.

### 9.4 Интерфейс (main.py)

1. **Кнопка «Улучшить промт»**
   - Разместить рядом с полем ввода промта (на вкладке «Запрос»), например в одной строке с «Сохранить промт» и «Отправить».
   - По нажатию: взять текущий текст из поля ввода; если пусто — предупреждение.

2. **Выбор модели**
   - В диалоге улучшения или в настройках: комбобокс «Модель для улучшения» — список активных моделей из models (те же, что для запросов). Сохранять выбор в settings (`prompt_improver_model_id`).

3. **Окно/панель результатов**
   - Открывать диалог (или панель) с блоками:
     - **Исходный промт** — только чтение.
     - **Улучшенный промт** — текст + кнопка «Подставить в поле ввода».
     - **Варианты переформулировки** — 2–3 варианта, у каждого кнопка «Подставить».
     - Опционально: блок «Под тип задачи» (код / анализ / креатив) с кнопками «Подставить».
   - Показ прогресса: пока запрос к API выполняется — индикатор или «Отправка…», кнопку «Улучшить» отключить (аналогично «Отправить» при основном запросе). Выполнять запрос в QThread, чтобы не блокировать UI.

4. **Подстановка в поле ввода**
   - По нажатию «Подставить» для выбранного варианта: закрыть диалог (если нужно), подставить выбранный текст в поле ввода промта (QTextEdit на вкладке «Запрос»). Пользователь может сразу отредактировать и отправить.

### 9.5 Интеграция и проверка

1. Проверить сценарий: ввод промта → «Улучшить промт» → выбор модели (или использование сохранённой) → получение улучшенного и вариантов → подстановка одного из них в поле ввода → отправка основного запроса.
2. Проверить поведение при пустом поле, при ошибке API, при нестандартном формате ответа модели.
3. Убедиться, что используется тот же Open Router–клиент и те же ключи (.env), без дублирования логики.

### 9.6 Порядок реализации (кратко)

1. Добавить в network.py поддержку запроса с `messages` (system + user) и функцию вызова для одной модели с системным промтом.
2. Создать модуль prompt_improver.py: системный промт, вызов network, парсинг ответа.
3. Добавить в settings хранение `prompt_improver_model_id` (и при необходимости текст системного промта).
4. В main.py: кнопка «Улучшить промт», диалог с выбором модели и отображением результата, кнопки «Подставить», выполнение запроса в потоке.
